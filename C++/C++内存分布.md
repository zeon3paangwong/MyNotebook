# C++ 内存管理全链路

## 一、内存分区（五区模型）

| 区域         | 内容                                         | 生命周期               | 分配方式              |
| ---------- | ------------------------------------------ | ------------------ | ----------------- |
| **代码区**    | 函数体、机器指令                                   | 程序运行期间             | 编译期确定             |
| **常量区**    | 字符串字面量、`const` 常量                          | 程序运行期间             | 编译期确定             |
| **全局/静态区** | `.data`（已初始化）+ `.bss`（未初始化）+ `.rodata`（只读） | 程序运行期间             | 编译期确定             |
| **栈**      | 局部变量、函数参数、返回地址                             | 函数调用结束自动释放         | 移动 `rsp` 指针       |
| **堆**      | `new`/`malloc` 动态分配                        | 手动 `delete`/`free` | `brk`/`mmap` 系统调用 |

> [!note] "动态区"两种口径
> - **按存储期**：栈（自动）+ 堆（手动）都属动态区
> - **按地址空间**：栈和堆平级，各自独立

## 二、内存开辟

### 栈开辟
cpp

void foo() {

int a; // 栈上分配，仅移动 rsp 寄存器

int b[100]; // 同样只移动 rsp

}

// 函数返回 → rsp 回退 → 自动释放
- **本质**：移动栈指针 `rsp`，O(1) 无开销
- **无碎片、无系统调用、无构造/析构**（POD 类型）

### 堆开辟（`new` 三步）
cpp

MyClass* p = new MyClass(42);
| 步骤 | 调用链 | 说明 |
|------|--------|------|
| 1 | `operator new` | C++ 层面分配原始内存 |
| 2 | `malloc` → `brk`/`mmap` | 向 OS 申请虚拟内存 |
| 3 | 构造函数调用 | 在分配的内存上构造对象 |

**系统调用层**：`brk`（小块，堆顶扩展）/ `mmap`（大块，匿名映射），实际物理页按需分页（缺页中断时才分配）

## 三、内存开销

| 开销项 | 说明 |
|--------|------|
| **chunk header** | `malloc` 内部管理头 8~16 字节 |
| **对齐填充** | 按 8/16 字节对齐，尾部可能浪费 |
| **`new[]` 元素计数** | 数组分配时头部额外存元素个数（供 `delete[]` 用） |
| **碎片** | 外部碎片（空闲块不连续）+ 内部碎片（对齐浪费） |
| **时间成本** | 系统调用 + 锁竞争 + 查找空闲块 |

> [!tip] 栈 vs 堆开销
> 栈：**零额外开销**，只有 `rsp` 移动。堆：header + 对齐 + 碎片 + 系统调用，开销显著。

---

## 四、内存释放

### 栈释放

函数返回 → `rsp` 回退 → 自动完成，零成本。

### 堆释放（`delete` 流程）
cpp

delete p;

| 步骤 | 说明 |
|------|------|
| 1 | 调用析构函数 |
| 2 | `operator delete` |
| 3 | `free` → 小块回 bin（不还给 OS），大块 `munmap` 直接归还 |

### 数组释放（`delete[]`）

> [!warning] 注意
> `delete[]` **不是**"取出第一块内存"，而是读头部存的 `n`，逆序析构 `n` 个对象。

---

## 五、关键易错点

| 坑 | 说明 |
|----|------|
| `delete` vs `delete[]` | 数组必须用 `delete[]`，否则只析构第一个元素 → 未定义行为 |
| `new` 不抛异常版本 | `new(std::nothrow)` 失败返回 `nullptr` |
| 内存泄漏 | 忘记 `delete` / 异常路径跳过 `delete` |
| 悬垂指针 | `delete` 后继续用指针 |
| 重复释放 | 同一指针 `delete` 两次 → 未定义行为 |
| 栈溢出 | 递归过深 / 栈上分配超大数组 |

## 六、现代 C++ 推荐做法
cpp

// 用智能指针代替裸 new/delete

std::unique_ptr<MyClass> p = std::make_unique<MyClass>(42);

std::shared_ptr<MyClass> sp = std::make_shared<MyClass>(42);

// 用容器代替裸数组

std::vector<int> arr(100); // 内部 new[]，析构自动 delete[]

> [!important] 核心原则
> **RAII + 智能指针 + STL 容器**，能不写 `new`/`delete` 就不写。

---

## 七、速查总结

| 操作 | 栈 | 堆 |
|------|----|----|
| 开辟 | 移动 `rsp`，O(1) | `new` → `malloc` → `brk`/`mmap` |
| 释放 | 函数返回自动回退 | 手动 `delete` → `free` |
| 开销 | 零 | header + 对齐 + 碎片 |
| 碎片 | 无 | 有（外部+内部） |
| 大小限制 | 小（MB 级） | 大（GB 级） |
| 速度 | 极快 | 较慢（系统调用+锁） |
